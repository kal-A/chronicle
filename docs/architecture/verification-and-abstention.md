# Verification and Abstention

## Verification Layers

1. **Schema:** typed records, enums, ranges, required provenance.
2. **Reference:** unique IDs and complete internal links.
3. **Evidence:** major Claims and NarrativeBlocks resolve to permitted Passages.
4. **Historical semantics:** time roles, location precision, dispute and classification wording.
5. **Source/rights:** acquisition, quotation/display, completeness, independence, and visibility.
6. **Relationship critic:** mechanism, alternatives, counterevidence, causal overstatement.
7. **Package completeness:** required outputs or explicit gaps.
8. **Interaction:** map/timeline/graph actions reference valid targets.

## Outcomes

- `pass`: valid for its declared draft/review state.
- `partial`: usable with explicit missing capabilities/coverage.
- `blocked`: cannot be rendered or published as a valid investigation.
- `abstained`: a requested conclusion/capability is intentionally not produced.

Verification results store rule ID/version, severity, affected record IDs, deterministic/model assessor provenance, message, and remediation. Model self-reported confidence never substitutes for a check.

## Mandatory Abstention Cases

- no passage supports a major claim;
- relevant full text was unavailable;
- citation location cannot be resolved;
- evidence is only a search snippet or metadata;
- relationship mechanism is merely chronological;
- source diversity is too weak for the requested conclusion;
- actor knowledge is inferred from availability rather than receipt/awareness evidence;
- map rights, period fit, or georeferencing are inadequate;
- request exceeds supported scope/domain;
- validation repeatedly fails.

## Publication Gate

Generated draft status is not public historical review. Publication additionally requires public visibility, rights clearance for displayed material, human review where required, immutable package/presentation revision, and a retained limitations report.
