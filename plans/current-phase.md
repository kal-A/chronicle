**Stage taxonomy** (from the adjusted plan §4, used verbatim, not "mock"-prefixed so it stays valid once C2+ replace the stubs): `SCOPE_PROPOSED → DISCOVERY_QUERIES_PREPARED → SOURCE_CANDIDATES_DISCOVERED → SOURCES_ASSESSED → CORPUS_PREPARED → HISTORICAL_MODEL_ASSEMBLED → INVESTIGATION_COMPOSED → VERIFIED`, ending in one of `ready | partial | abstained | failed`.

**Built:**
- `backend/src/chronicle/workflow/` — `RunRecord`/`StageRecord` Pydantic models (fields per the adjusted plan §7), and `engine.py`'s `generate()`/`resume()`/`run_pipeline()`/`run_stage()`. Reuse-vs-rerun is decided per stage by comparing the current input's hash against the hash on that stage's last `PASSED` attempt — since each stage's input is exactly the previous stage's output, a changed upstream result automatically produces a different hash at the next stage, so downstream invalidation needs no separate bookkeeping pass.

- **A real circular import was hit and fixed during implementation**, not shipped: `workflow/__init__.py` eagerly re-exporting from `engine.py` (which imports `RunStore` from `storage`, which imports from `workflow.stages`/`state`) created a cycle depending on import order. Fixed by having `workflow/__init__.py` only re-export the cycle-free `stages`/`state` modules; consumers import `chronicle.workflow.engine` directly.

## Phase P3 — capability proof (in progress)

P3 proves the arc's actual thesis: the *same* code path researches an *arbitrary* topic (capability, never a single event). **First proof (pre-fix) findings — the real blocker was NOT the pre-registered DIRECT-grounding gap.** All three topics discovered + acquired real free sources and built valid corpora (generality holds; no event-hardcoding). But the local 7B model produced *structurally-invalid agent output* that **hard-FAILED** runs before they even reached the grounding gate: **A** FAILED because the planner's initial plan carried a `search_passages` call with `dateRange` but no `dateRoles` (a Pydantic cross-field rule the planner's shape check does not enforce → runner preflight REJECTED → mapped to FAILED); **B** FAILED because the planner emitted an invalid counterevidence plan (`PlannerValidationError`). **Fix — generalize abstain-not-fail to the whole workflow (robustness first; Kamal's explicit choice).** Model-*output*-validation failures now terminate as a principled **ABSTAINED** with an honest, specific reason; genuine boundary/system errors still **FAILED**. So the map has no geography to render and 8 of 10 typed retrieval tools have nothing to retrieve. This slice implements extraction → geolocation → assembly as a **capability**, subject-agnostic, opt-in, against the contracts that already exist (no new spec).

**Historicity is a hard requirement (Kamal, 2026-09-12).** A 17th-century investigation must be placed with 17th-century-accurate geography, never a modern basemap. The geo layer is period-aware by construction and never asserts a modern-as-historical location.

**Built (all in `backend/src/chronicle/acquisition/`, TDD, anti-topic-branching guard extended to cover it):**
- **`geocoding.py` (stage 12)** — a pluggable, period-aware resolver. `GeoProvider` protocol; `WorldHistoricalGazetteerProvider` (preferred — period-scoped records; a **period-overlap guard rejects a place whose attested timespan doesn't overlap the investigation**); `WikidataGeoProvider` (broad-coverage SPARQL/WKT fallback); `PeriodAwareGeocoder` tries providers in order, skips one that raises, and returns **coordinates=None rather than inventing a point** when nothing can place the name in period. Both sources free; others (Pleiades, OpenHistoricalMap, GeoNames) addable behind the same interface. Injected `httpx.Client` + `MockTransport` → zero-network tests.
- **`extraction.py` (stage 7)** — `extract_events(passages, period, topic, provider)`: one schema-constrained model pass proposes `ExtractedEvent{title, placeName, year, passageIds}`; the schema bounds the year to the investigation range and enum-locks citations to real passage ids. A post-generation `_ground()` that **does not trust the model** drops any event citing a non-real passage, strips fabricated ids, drops an event left ungrounded, and drops an out-of-range (anachronistic) year. Empty passages → no model call. Everything is a `PROPOSED` draft.
- **`assembly.py` (stages 7→9/12 glue)** — `assemble_enrichment(...)` runs extraction, geolocates each distinct place name *for the period* (once, cached per name), and assembles the contract records the workspace renders from: a `PlaceEntity` per place (period-accurate coordinates when located, else low-precision/no-coordinate), a `GeneratedEvent` per event (located + grounded, `PUBLIC`/`PROPOSED`), a canonical reverse-indexed `GeneratedEvidenceLink` per passage→event citation (`targetType=event`, `role=supporting`), and a chronological `TimelineEntry` per event. Owns a `*-ev-*` id namespace so it merges cleanly with the scope scaffolding.

**Wired (opt-in, additive — existing behavior byte-identical when off):**
- `corpus_builder.build_corpus` gained an optional `enrich: Callable[[list[Passage]], Enrichment]` run over the *built* passages (so evidence links cite the real assigned ids). When it yields events: events/timeline/evidenceLinks are populated, the scene surfaces the events, a duplicate scope stub is dropped in favour of the richer located place, and **the timeline capability flips on** (`Facet.TIMELINE`, `timeline` removed from `omittedCapabilities`), with honest updated omissions. The **map capability deliberately stays omitted**: the contract couples it to a raster `MapAsset` (Rule 15) — the exact "found online" model being moved away from — so Slice 1 produces the *geographic data* (coordinates) and the generated-map *rendering* is Slice 2; never advertise a capability the workspace can't yet render for this corpus. Empty enrichment → the corpus stays evidence-only exactly as before.
- `AcquisitionPipeline` takes optional `extractor` + `geocoder` (both required to enable enrichment); `AcquisitionResult` reports `events` + `located_places`.
- `acquisition/defaults.py` adds `default_geocoder()` (WHG + Wikidata) and passthrough params; `api/app.py` gates enrichment behind **`CHRONICLE_ENABLE_EXTRACTION=1`** (off by default, mirroring the `CHRONICLE_ENABLE_SEMANTIC` opt-in precedent; reuses the agents' Ollama provider). `scripts/acquire_smoke.py` gains `--enrich` for live verification.

**Live verification surfaced a historicity bug — and the fix is the point.** The first live Great Fire build (7B-GPU, 5 real sources incl. two 1666 Gutenberg primary narratives, 138 passages) produced exactly the intended shape — 1 grounded event, `timeline_capable=True` — **but placed the Great Fire at (42.97, -81.25): London, _Ontario, Canada_.** Both geo providers returned the wrong "London": WHG's free `/api/index` isn't prominence-ranked (it returns the Canadian London first; the English one is the 3rd feature, and the coordinate-bearing GB record carries no timespan so the period guard can't separate it from the Canadian one), and Wikidata's `LIMIT 1` exact-label match had no disambiguation at all. This is precisely the "never assert modern-as-historical" failure Kamal's hard requirement targets, so it blocked the commit.

**Fix (geocoding.py, defaults.py).** Wikidata now orders candidates by **sitelink count** (prominence — London, England has 356 vs Ontario's 86) and **rejects any candidate whose inception postdates the investigation** (Ontario founded 1826 > 1666), mirroring the gazetteer's period guard; the SPARQL literal is now escaped. WHG now **prefers an in-period attested feature over a period-agnostic one** rather than taking the first point feature. The default resolver is reordered **Wikidata-first** (documented: WHG's free index can't prominence-rank common names; it stays as a period-aware fallback and future source of period-accurate `nameAtTime`). Re-verified live: `default_geocoder().resolve("London", 1666)` → **(51.5072, -0.1275) London, England, via wikidata**. Known limitation: `nameAtTime` is currently the modern canonical label (an honest approximation; period-name refinement from the gazetteer is a later enhancement).

**Verification.** Full backend suite **777 passed, 4 skipped**; anti-topic-branching guard green (now scanning the new modules). New tests: `test_geocoding.py` (13 — period-overlap rejection, no-invented-coordinates, **prominence disambiguation, anachronistic-inception rejection, in-period preference**, provider chaining/fallback/resilience), `test_extraction.py` (6 — grounding + anachronism + fabricated-id guards, empty/no-call), `test_assembly.py` (5 — located vs honestly-unlocated place, grounded reverse-indexed evidence, chronological timeline, shared/distinct places, empty), plus builder/pipeline integration tests (timeline-flip, scope-stub dedup, unlocated event survives, empty stays evidence-only, end-to-end injected enrichment). Live Great Fire end-to-end (post-fix, 7B-GPU): discovered=6, acquired=5 (incl. two 1666 Gutenberg primary narratives), 138 passages → **1 grounded event, `located_places=1`, `timeline_capable=True`, event located at London (51.507, -0.128) — London, England**, package `status=partial`. The capability produces period-accurate generated geography + a timeline, fully grounded, subject-agnostically.

## Phase P3 — structured extraction (Slice 2): the generated map

**Why.** Slice 1 produced the geographic *data* (located places + coordinates) but deliberately left "map" omitted, because the workspace only knew how to render a *found* raster plate (`Scene.mapLayer`, sourced from a `mapScene`→`mapAsset`); generated corpora have no such plate and fell back to a toy 2-node `SchematicMap` that ignores coordinates. This slice makes the map **built up from the investigation's own data**, per Kamal's direction ("the main map should be generated, not found online") and the historicity requirement.

**Decision (Kamal): basemap = self-contained graticule, on the workspace's real map canvas.** Of the documented options (OpenHistoricalMap date-filtered tiles / neutral physical layer / graticule), the graticule-only basemap was chosen: zero new assets, zero network, fully offline, historically neutral — it asserts no borders, coastlines, or labels, only the located points in real coordinate space. Crucially it is rendered on the **same MapLibre GL canvas** the curated `HistoricalMap` uses (Kamal's steer: "we'd use WebGL"), not a static diagram — generated and curated investigations now share one pannable/zoomable interaction model, differing only in the basemap layer. (OHM/period basemaps remain a later enhancement that slots into the same canvas.)

**Built:**
- **`map/MapView.tsx` — `GeneratedMap` (new, MapLibre GL).** The same WebGL canvas as `HistoricalMap`, but its basemap is built rather than found: a **bundled neutral physical basemap** (Natural Earth 1:110m land / coastlines / rivers / lakes, public domain, in `public/basemap/`, served from the app — no tiles, no network) under a generated lat/lng graticule, with `fitBounds` (a `maxZoom` clamp so a lone point lands on a regional frame the coarse basemap can render, not a blocky close-up). **No political borders or labels** — only period-stable physical geography — so the map never asserts an anachronistic boundary. Located places are a **GL circle layer from a GeoJSON source** (not DOM markers): a crisp centre dot at the representative coordinate plus an **uncertainty halo sized by the place's `LocationPrecision`** (building→tight … approximate→large, soft), so a marker never implies more spatial precision than the evidence supports; a hover popup (closeOnMove) names each place. Because the points render in the same GL pass as the basemap they stay exactly registered — no pan/zoom drift — and scale to many places. Like `HistoricalMap` the canvas is an `aria-hidden` progressive enhancement that no-ops under jsdom/no-WebGL; the accessible location list stays the first-class interaction, plus an always-present provenance note. `MapView` now branches: raster `mapLayer` → `HistoricalMap`; else places-with-coordinates → `GeneratedMap`; else (no geography) → `SchematicMap` (honest — nothing to plot). Styles in `index.css`; basemap source documented in `docs/research/generated-map-basemap-source.md`.
- **`corpus_builder.build_corpus` — map capability flip.** The `map` capability lights up (removed from `omittedCapabilities`, `Facet.MAP` enabled) exactly when at least one place is located with coordinates — the generated map, not a raster asset — and stays omitted when nothing is located (no empty canvas promised).

**Three things the visual passes drove, not shipped blind:** (1) the first WebGL render was blank — MapLibre 5.x rejects `glyphs: undefined` in a style (the key must be omitted, not set to `undefined`); jsdom's try/catch had swallowed it, so only the in-browser check surfaced it; fixed. (2) Kamal's reaction to the first render — "there's no map, it's all dots in a graph" — was correct: a bare graticule is a scatter plot, not a map; adding the Natural Earth physical basemap under the points turned it into a real map (recognizable European coastlines with the cities on land), historicity intact (no political borders) and offline. (3) Kamal then noticed markers **drifting against the basemap during pan/zoom** — the tell of the deeper default assumption that "a place is a DOM pin." The places were HTML `maplibregl.Marker` overlays (a separate DOM layer that lags the GPU canvas during motion) and each was an identical pinpoint dot. Fixed by treating located places as **data on the map**: a GL circle layer whose marker size encodes the evidence's `LocationPrecision`. This removes the drift (same render pass), scales, and — the point that matters for the investigation/LLM layer — stops the map overstating spatial certainty the evidence doesn't have (the coordinate is a geocoder-attached rendering aid with a precision; grounding is the place name + passages).

**Verification.** Frontend — `npm run typecheck`, `npm run lint`, `npm run build` all clean; **vitest 120 passed** (incl. `MapView.test.tsx`: the generated-map branch renders its provenance note when coordinates exist and there's no raster layer; falls back to the schematic when no place is located — the WebGL canvas itself no-ops under jsdom, as with `HistoricalMap`). Backend — **777 passed / 4 skipped** (builder tests updated: map flips on with a located place, stays omitted when unlocated). Guard green. Basemap GeoJSON ships in the production build (`dist/basemap/`). **Visual pass done in a real browser** against the actual MapLibre config (Great Fire single point + a multi-city spread): the physical basemap (European coastlines/rivers), markers on land, focus ring, and pan/zoom all render correctly.

**Deferred:** see ADR-004 for the full arc (labels → time cursor → territories). Also: flip `CHRONICLE_ENABLE_EXTRACTION` on by default once latency/quality are confirmed on the target host; a higher-resolution (1:50m) offline physical set for closer detail.

## Phase P3 — generated map: on-map labels + ADR-004 (the map as an instrument)

Kamal's direction after Slice 2: the map needs to become an *instrument*, not a locator — on-map **labels** (with an option to toggle classes off), **territories** of control/influence (e.g. 2nd Punic War: Carthage vs. Rome control + spheres), and **evolution over the event's timeline** (scrub a slider, the map changes), all **in tandem with the LLM**. Two outputs this slice:

**ADR-004 (proposed) — `docs/decisions/ADR-004-time-indexed-grounded-geography.md`.** Records the durable data-model decision before building the big pieces: **the map is a JOIN indexed by a single `currentTime` cursor** — the LLM extracts grounded who/what/when claims (incl. a new `ControlState` record for control/influence/contested, passage-grounded, time-valid), **sourced datasets provide geometry** (gazetteers for points, historical-boundary datasets for polygons — never LLM-drawn), and one time cursor drives which slice renders. Binding honesty guardrails: geometry only from sourced data; influence/contested render fuzzy; no period geometry ⇒ omit or explicit approximation, never a fabricated frontier; temporal interpolation shown as uncertainty. Sequenced: labels → one time cursor → territories → deeper LLM tandem. Indexed in `docs/decisions/README.md`.

**Labels slice (built).** `map/MapView.tsx` `GeneratedMap` now renders on-map place names as a GL `symbol` layer (`text-field` from the place name), powered by **bundled OFL font glyphs** (Noto Sans, `public/basemap/fonts/NotoSans-Regular/{0-255,256-511,8192-8447}.pbf`, from protomaps' public asset repo) — served from the app, no external font fetch, consistent with the offline basemap. Labels use a halo for legibility and `text-optional` collision so crowded labels drop rather than overprint. An accessible **Hide/Show place labels** toggle (`aria-pressed`, outside the aria-hidden canvas) flips the layer's visibility; rank-based class toggling is the noted later refinement. **Verification:** frontend typecheck/lint/build clean, **vitest 121 passed** (new `MapView.test.tsx` case: the toggle renders, is accessible, and flips pressed state); glyphs ship in `dist/basemap/fonts/`; in-browser visual pass confirmed labels render legibly beside the located points over the physical basemap. This realizes ADR-004 step 1.

**ADR-004 addendum + territory/time-cursor prototype (design).** Before building the territory pieces, a throwaway visual prototype (scratchpad harness, not in the codebase) locked the coloration/interaction language against real MapLibre GL and the user's reference maps: **control** = solid polity tint, **influence** = diagonal hatch, **contested** = two-color stripe, all **smoothed and clipped to the coastline** (fluid, never floating over sea); a **legend docked in a rail outside the map** ("Style A", never covering territory); and one **time cursor over discrete sourced snapshots, step-held** with an honest "as mapped ~Y" between keyframes. The renderer is subject-agnostic (`{ polities, snapshots:[{ year, bands }] }`, colors by polity index) and was proven on two datasets. That design is written up as **`docs/decisions/ADR-004-addendum-territory-time-implementation.md`** (proposed) — the production build plan: the `ControlState` contract record (carrying a `geometryRef`, never geometry), a `territoryGeometries` collection tagged with source/attested-year/license, a `territory` facet flip, honesty validation rules, a deterministic name+year→polygon geometry resolver (no match ⇒ omit), a new `acquisition/control_state.py` extraction stage, and six slices (T1 cursor → T2 contract → T3 dataset+resolver → T4 render → T5 extraction → T6 tandem). Linked from ADR-004 and `docs/decisions/README.md`.

**ADR-004 step 2 — Slice T1: the generated map's markers answer the single time cursor (built).** The workspace already drives one temporal cursor (`TemporalMapRail` → `selectedEventIndex` → `timeVisibleEventIds` → `MapView`'s `eventIds` → `visibleEvents`), and `HistoricalMap` already fades dormant markers by it — but `GeneratedMap` ignored the window and rendered every located place identically, so scrubbing did nothing on it. Fixed: each place's GeoJSON now carries its count of currently-visible events and an `active` flag; the GL layers style by it — dormant places (no event visible yet at the cursor) render a smaller, muted, halo-less dot with a dimmed label, and light up (full halo sized by precision, bright core, full label) when the cursor reaches their events. The existing `setData` effect already re-fires on `visibleEvents`, so scrubbing the rail now visibly evolves the generated map, matching `HistoricalMap`. The pure GeoJSON builder moved to `map/generatedMapGeo.ts` (so the component file only exports components — keeps fast-refresh + the warning-free lint baseline) and is unit-tested directly for time responsiveness (jsdom can't render the GL canvas). **Verification:** frontend typecheck / lint (warning-free) / build clean; **vitest 123 passed** (2 new `placesToGeoJSON` cases: active/eventCount reflect the visible-event window; focused + defensive precision). No contract change; no backend change. Live in-app visual verification is pending a multi-place generated corpus (current live-acquired corpora locate a single place); a dev-only harness (`map-harness.html` + `src/devMapHarness.tsx`, not built into `dist`) mounts the real `MapView` with a synthetic multi-place scene + a slider driving `eventIds` for eyeballing. This realizes ADR-004 step 2.

**ADR-004 step 3 — Slice T2a: the time-indexed territory contract (shapes, both stacks, additive).** The record shapes for the territory layer, added in exact parity to `backend/src/chronicle/contracts/generated_investigation.py` and `src/features/investigation/model/generatedInvestigation.ts`, plus enums: **`ControlState`** `{ id, polity, kind: controlled|influence|contested, validFrom, validTo, geometryRef, precision, evidenceLinkIds, reviewStatus, visibility }` — a passage-grounded, time-valid assertion that carries **no geometry**, only a `geometryRef`; **`TerritoryGeometry`** `{ id, type: Polygon|MultiPolygon, coordinates, sourceDataset, attestedYear, license, polity? }` — a boundary polygon resolved from a sourced dataset, tagged with the snapshot year it came from (`attestedYear`, BC = negative) and its provenance/licence; new `ControlStateKind` + `GeometryType` enums; a new `territory` `Facet`. Both attach to `GeneratedInvestigation` as **optional/additive** collections (`controlStates`, `territoryGeometries`) — every existing package stays valid without them (backend defaults to `[]`, frontend `.optional()`). **No rendering, and no cross-record rules yet** — those (geometryRef resolves, evidence grounding, the honesty coupling that only `controlled`+boundary-sourced renders a firm edge, and the `territory` facet flip) are Slice T2b, kept separate so each is independently verifiable. **Verification:** backend **788 passed / 4 skipped** (new `tests/contract/test_control_state.py`: the record shapes accept valid data, reject malformed — empty evidence, unknown kind, empty geometry, bad type — and the golden package round-trips both with and without the additive layer); frontend typecheck / lint (warning-free) / build clean, **vitest 128 passed** (parity cases mirroring the Python tests); anti-topic-branching guard green (the shapes live in `contracts/`, not a scanned package; the eventual `acquisition/control_state.py` extractor of Slice T5 is what the guard will cover). This begins ADR-004 step 3.

**ADR-004 step 3 — Slice T2b: the territory-layer cross-record rules (Rule 22, both stacks, parity).** With the shapes in place, `ControlState` becomes a first-class *grounded* record, enforced identically in `backend/src/chronicle/contracts/validation.py` and the `validateGeneratedInvestigation()` mirror in `generatedInvestigation.ts`: (1) **`controlState` is now a real evidence target** — added to `EvidenceTargetType` and wired into Rule 2 (id uniqueness), Rule 5 (link → typed target) and Rule 5b (bidirectional reverse-index), so a `ControlState` is grounded exactly like a claim or event, not with a looser check. (2) **New Rule 22:** every `ControlState` needs ≥1 **supporting** `EvidenceLink` (grounded via `_evidence_for` / `evidenceFor`); its `geometryRef` must resolve to a `TerritoryGeometry`; its interval must be ordered (`validFrom.earliest ≤ validTo.latest`); **`influence`/`contested` may not claim `building`/`city` precision** (only region/approximate — the honesty rule that fuzzy reaches get no crisp frontier, the territorial parallel of Rule 15's marker-precision gate); and a declared `territory` facet must have ≥1 `ControlState` behind it. The honesty coupling that *renders* a firm edge only for `controlled` + boundary-sourced geometry is a **rendering** concern (Slice T4), and the `territory` facet **auto-flip** belongs with the extractor that produces control states (Slice T5) — neither is in T2b. **Verification:** backend **794 passed / 4 skipped** (6 new Rule-22 cases: grounded package validates; rejects missing-support, unresolved geometryRef, reversed interval, fuzzy-at-city-precision, and a territory facet with no data); frontend typecheck / lint (warning-free) / build clean, **vitest 135 passed** (parity cases mirroring the Python tests). Anti-topic-branching guard green. Contract for the territory layer is now complete; next is Slice T3 (a bundled historical-boundaries dataset + the deterministic name+year→polygon geometry resolver).

**ADR-004 step 3 — Slice T2c: de jure ↔ de facto control basis (both stacks, additive).** Kamal's steer ("include areas of sovereignty, control, influence whenever relevant") surfaced that `kind: controlled` conflated a polity's own homeland with land it merely holds. Rather than split the primary `kind`, two optional fields refine controlled territory (chosen granularity: **Core, 3 values**): **`basis`** = `sovereign` | `occupied` | `administered` (homeland / held-by-force / colony-protectorate-mandate-client), and **`sovereignPolity`** = the de jure owner, named only during non-sovereign control. This is the foundation for the map to render held-not-owned land (e.g. German-occupied France) as the controller textured over the sovereign, and for the T5 extractor to classify occupation vs homeland. Both optional/additive (existing packages unaffected); `ControlBasis` enum added to both stacks. Rule 22 gains honesty checks: `basis` applies only to `controlled`; a named `sovereignPolity` requires a non-sovereign `basis` and must differ from the controller. Rendering keys off `basis` (T4); the extractor fills it and abstains when unclear (T5). **Verification:** backend **799 passed / 4 skipped** (5 new cases); frontend typecheck / lint (warning-free) / build clean, **vitest 139 passed** (4 new parity cases); guard green. ADR-004 addendum's ControlState definition updated to match.
